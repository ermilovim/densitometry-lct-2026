# Развёртывание сервиса

## Быстрый запуск для проверяющих

Требуется Linux x86_64 с установленным и запущенным Docker. Для быстрого
инференса рекомендуется NVIDIA GPU, драйвер с поддержкой CUDA 12.8+ и NVIDIA
Container Toolkit. Без доступной для Docker видеокарты сервис запустится на CPU.
Для первого запуска также нужен исходящий HTTPS-доступ к `ghcr.io`, PyPI,
`download.pytorch.org` и Dropbox.

Из корня полученного репозитория выполните одну команду:

```bash
./scripts/deploy.sh
```

При первом запуске скрипт скачает проверенный checkpoint 3D-модели, соберёт
Docker-образ, запустит контейнер и дождётся успешного ответа `/api/health`.
Интерфейс будет доступен по адресу:

```text
http://<IP-адрес-сервера>:8765
```

Сервис не содержит пользовательской авторизации, поэтому прямую публикацию
`0.0.0.0:8765` следует использовать на изолированном проверяющем стенде или за
сетевым доступом организаторов.

Повторный запуск той же команды безопасно обновляет контейнер. Загруженные
исследования и результаты сохраняются в `artifacts/viewer_jobs`, checkpoint — в
`artifacts/dxa3d`. Если новый контейнер не проходит health check, скрипт
возвращает предыдущий контейнер.

## Что проверяет скрипт

- наличие Docker, `curl` и доступ к Docker daemon;
- корректность порта и режима GPU;
- не менее 8 ГиБ свободного места перед сборкой;
- SHA-256 скачанного и уже существующего checkpoint;
- доступ Docker к NVIDIA GPU;
- запуск контейнера и ответ `/api/health` в течение 60 секунд.

Если GPU или NVIDIA Container Toolkit недоступны, `GPU_MODE=auto` включает
CPU-режим. Чтобы считать отсутствие GPU ошибкой, используйте:

```bash
GPU_MODE=require ./scripts/deploy.sh
```

## Настройки

Все настройки задаются перед той же командой:

```bash
VIEWER_PORT=9000 VIEWER_BIND=127.0.0.1 GPU_MODE=require ./scripts/deploy.sh
```

| Переменная | Значение по умолчанию | Назначение |
|---|---:|---|
| `VIEWER_PORT` | `8765` | Порт на сервере |
| `VIEWER_BIND` | `0.0.0.0` | Адрес публикации; `127.0.0.1` для reverse proxy |
| `GPU_MODE` | `auto` | `auto`, `require` или `off` |
| `VIEWER_JOBS_DIR` | `artifacts/viewer_jobs` | Постоянное хранилище заданий |
| `DXA3D_MODEL_DIR` | `artifacts/dxa3d` | Каталог checkpoint 3D-модели |
| `IMAGE_NAME` | `densitometry-qc:latest` | Имя Docker-образа |
| `CONTAINER_NAME` | `densitometry-qc` | Имя контейнера |

## Частые проблемы

### Нет доступа к Docker

Сообщение `Docker daemon is unavailable` означает, что Docker не запущен или у
текущего пользователя нет прав на сокет. Проверьте:

```bash
docker info
```

На стенде с `sudo` запуск можно выполнить так:

```bash
sudo ./scripts/deploy.sh
```

### Docker не видит GPU

Проверьте обе команды:

```bash
nvidia-smi
docker run --rm --gpus all nvidia/cuda:12.8.1-base-ubuntu24.04 nvidia-smi
```

Если первая работает, а вторая нет, установите или исправьте NVIDIA Container
Toolkit. До этого `GPU_MODE=auto` позволит проверить интерфейс в CPU-режиме.

Если Docker видит GPU, но обработка медленная или завершается из-за памяти,
проверьте сторонние процессы командой `nvidia-smi`. На время проверки модели
нужно освободить видеопамять от других inference-сервисов.

### Порт уже занят

Выберите другой порт:

```bash
VIEWER_PORT=8877 ./scripts/deploy.sh
```

Проверить занятый порт можно командой `ss -ltnp | grep :8765`.

### Не скачиваются веса

Серверу нужен исходящий HTTPS-доступ к Dropbox. Загрузка атомарная: незавершённый
`.part` не используется, а контрольная сумма проверяется до запуска. После
восстановления сети просто повторите `./scripts/deploy.sh`.

Если сборка останавливается при скачивании Python-пакетов или базового образа,
проверьте исходящий HTTPS-доступ к `ghcr.io`, `pypi.org`,
`files.pythonhosted.org` и `download.pytorch.org`. В закрытой сети Docker daemon
и сам shell должны использовать настроенный организаторами proxy.

### Контейнер запущен, но сайт недоступен

Проверьте состояние и последние сообщения:

```bash
docker ps --filter name=densitometry-qc
docker logs --tail 100 densitometry-qc
curl -fsS http://127.0.0.1:8765/api/health
```

Если локальный `curl` работает, разрешите TCP-порт `8765` в firewall или
security group стенда. При использовании Nginx задайте `VIEWER_BIND=127.0.0.1`
и воспользуйтесь конфигурацией `deploy/nginx/densitometry.conf`.

### Остановка и повторный запуск

```bash
docker stop densitometry-qc
./scripts/deploy.sh
```

Удаление контейнера не удаляет задания и checkpoint, потому что они хранятся в
каталогах репозитория и подключаются как bind mounts.
